# v6.0.0 Breaking Changes Plan

**Status:** READY TO IMPLEMENT
**Target Release:** 2026-05 (Q2 2026)
**Current Version:** v5.18.0
**Linear Issue:** INF-1546

---

## Context

This major version consolidates breaking changes into a single release, so consumers update
once rather than facing multiple sequential breaks:

1. **INF-1546**: Enable cross-region replication on the ALB access log bucket (audit trail DR)
2. **Deprecated typo variables**: Remove `alb_healthcheck_uhealthy_threshold` and
   `attach_tagret_group_to_asg` (deprecated since v5.7.0, removal announced for v6.0.0)
3. **Always-on access logging**: Remove `alb_access_log_enabled` variable; bucket always created
4. **Alarm requirement**: Enforce at least one of `alarm_emails` or `alarm_topic_arns`

The access log bucket migrates from a raw `aws_s3_bucket` to the `infrahouse/s3-bucket/aws` module
(v0.6.0), which ships CRR built-in via its `replication_region` variable.

---

## Breaking Changes Summary

| Change | Consumer action required |
|--------|------------------------|
| `replication_region` required (no default) | Add `replication_region = "us-east-1"` |
| Remove `alb_access_log_enabled` | Remove the variable from calls (logging is always on) |
| Remove `alb_healthcheck_uhealthy_threshold` | Rename to `alb_healthcheck_unhealthy_threshold` |
| Remove `attach_tagret_group_to_asg` | Rename to `attach_target_group_to_asg` |
| Require alarm config | Add `alarm_emails` or `alarm_topic_arns` if not already set |
| Drop AWS provider 5.x | Upgrade to `hashicorp/aws ~> 6.0` |
| Access log bucket moves to module | No action (handled by `moved` blocks) |

### 2. Replace raw S3 resources with `infrahouse/s3-bucket/aws` module

**File:** `s3.tf` (rewrite)

Replace all raw resources (`aws_s3_bucket.access_log`, `aws_s3_bucket_public_access_block`,
`aws_s3_bucket_server_side_encryption_configuration`, `aws_s3_bucket_versioning`,
`aws_s3_bucket_policy`) with:

```hcl
module "access_log" {
  source  = "registry.infrahouse.com/infrahouse/s3-bucket/aws"
  version = "0.6.0"

  bucket_prefix      = "${var.alb_name_prefix}-access-log-"
  bucket_policy      = data.aws_iam_policy_document.access_logs.json
  force_destroy      = var.alb_access_log_force_destroy
  enable_versioning  = true
  replication_region = var.replication_region

  tags = merge(
    local.default_module_tags,
    {
      VantaContainsUserData = false
      VantaContainsEPHI     = false
    }
  )
}
```

**ELB policy (circular dependency workaround):** The s3-bucket module accepts `bucket_policy`
as input, but we can't reference the module's own output (bucket ARN) in the input without a
cycle. Use prefix-wildcard for the bucket ARN:

```hcl
data "aws_iam_policy_document" "access_logs" {
  statement {
    principals {
      type        = "AWS"
      identifiers = ["arn:aws:iam::${local.elb_account_map[local.region]}:root"]
    }
    actions   = ["s3:PutObject"]
    resources = ["arn:aws:s3:::${var.alb_name_prefix}-access-log-*/AWSLogs/${local.account_id}/*"]
  }
}
```

The wildcard covers only the random suffix AWS appends. Combined with the specific prefix and
`AWSLogs/${account_id}/` path, this is tightly scoped.

**Note:** The s3-bucket module already enforces SSL-only access and denies KMS uploads internally,
so we drop the `AllowSSLRequestsOnly` statement from our custom policy.

### 3. Add `moved` blocks for state migration

**File:** `moved.tf` (new file)

Resource name mapping verified against s3-bucket module source:
- `aws_s3_bucket.this` (main.tf:1)
- `aws_s3_bucket_public_access_block.public_access` (main.tf:30)
- `aws_s3_bucket_server_side_encryption_configuration.default` (encryption.tf:1)
- `aws_s3_bucket_versioning.enabled` with count (versioning.tf:1)
- `aws_s3_bucket_policy.this` (main.tf:38)

```hcl
moved {
  from = aws_s3_bucket.access_log[0]
  to   = module.access_log.aws_s3_bucket.this
}

moved {
  from = aws_s3_bucket_public_access_block.public_access[0]
  to   = module.access_log.aws_s3_bucket_public_access_block.public_access
}

moved {
  from = aws_s3_bucket_server_side_encryption_configuration.access_log[0]
  to   = module.access_log.aws_s3_bucket_server_side_encryption_configuration.default
}

moved {
  from = aws_s3_bucket_versioning.access_log[0]
  to   = module.access_log.aws_s3_bucket_versioning.enabled[0]
}

moved {
  from = aws_s3_bucket_policy.access_logs[0]
  to   = module.access_log.aws_s3_bucket_policy.this
}
```

Consumers who had `alb_access_log_enabled = true` get a clean plan (no destroy/recreate).
Consumers who had it `false` (no bucket in state) simply get a new bucket created.

### 13. Validation for `alb_name_prefix` length

The s3-bucket module requires `bucket_prefix` <= 29 chars when replication is enabled.
Our prefix is `"${var.alb_name_prefix}-access-log-"` (adds 12 chars).
So `alb_name_prefix` must be <= 17 chars.

Add/update validation on `alb_name_prefix`:
```hcl
validation {
  condition     = length(var.alb_name_prefix) <= 17
  error_message = "alb_name_prefix must be <= 17 characters (S3 replication prefix limit)."
}
```
